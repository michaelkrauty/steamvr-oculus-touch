# cv1touch v0.3.0

This release brings a Windows installer, live sensor hotplug and recalibration,
more resilient tracking and diagnostics, and a broad CPU/allocation cleanup.

## Highlights

- **Windows installer:** install the daemon, SteamVR driver, and tools without
  building them. Sensor setup uses Windows' own WinUSB driver. The installer is
  unsigned, and sensor-driver setup asks for elevation separately. Windows build
  and install/uninstall tests pass; **Windows gameplay is not yet validated**.
- **Sensors can come and go:** the daemon notices USB changes while running. A
  bumped sensor can be recalibrated against the remaining stationary sensors;
  the rest of the room's calibration and registration stay in place. See the
  [requirements and limits](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/self-recalibration.md).
- **Less tracking CPU work:** fewer temporary allocations, redundant clock fits,
  projection/Jacobian calculations, covariance inversions and unnecessary native
  searches. This release pass also reuses ingress buffers and removes per-LED
  sorting during sensor refinement. Offline benchmarks and equivalence tests are
  documented; these are **not motion-to-photon latency measurements**.
- **Tracking and alignment polish:** quicker reacquisition, corrected angular
  prediction, better controller-model fitting and Lighthouse registration, plus
  more resilient behavior through radio gaps and engine restarts.
- **Controls and diagnostics:** bind the right Oculus button per game, retain
  latency/prediction settings, use `setup --redo STAGE`, stop the daemon with
  `cv1touch stop`, and collect a support bundle with `cv1touch report`. Logging
  and failure handling are bounded so blocked output does not stop tracking.

See the [full changelog](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/CHANGELOG.md)
for details, including measurement qualifications and recovery limitations.

## Install

**Windows 11 x64:** download `cv1touch-setup-0.3.0.exe` below, quit SteamVR, and
follow [the Windows guide](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/windows.md).

**Linux x86-64:** install the
[build dependencies](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/setup.md#build-dependencies),
quit SteamVR, then:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/michaelkrauty/steamvr-oculus-touch.git
cd steamvr-oculus-touch
python3 scripts/install.py
```

The attached `steamvr-oculus-touch-0.3.0.tar.gz` contains the complete source,
including the modified acquisition engine and pinned OpenVR SDK. Extract it and
run the same installer from its root; Git is not required. Linux native libraries
come from your distribution, so no prebuilt Linux binaries are supplied.
`SHA256SUMS` covers the source archive and Windows installer.

New installations need device access and physical calibration. Run
`cv1touch doctor`, then follow
[guided setup](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/setup.md#guided-setup).

## Upgrade from v0.2.0

**Update the daemon and SteamVR driver together.** The shared-memory ABI changed
from v3 to v4; mixed releases cannot exchange poses. Quit SteamVR, install v0.3.0,
restart the daemon (`systemctl --user restart cv1touchd` on Linux), then restart
SteamVR. Existing calibration and settings are retained. Run `cv1touch doctor`
and `cv1touch setup --check` afterward.

Controllers now appear as **Oculus Touch (cv1touch)**. Games inherit Oculus Touch
bindings, but custom bindings for the previous controller type may need to be
selected or recreated. Read the
[upgrade and rollback notes](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/setup.md#upgrade)
before switching versions.

## Limits

This remains an early release. Physical validation covers one Linux installation,
one controller pair, and up to five CV1 sensors; software tests do not establish
broader hardware or game compatibility. Tracking needs camera visibility and
overlap. Rift S and Quest Touch controllers and controller pairing are not
supported. The CV1 headset is used as a USB radio receiver, not as a display.
See [validation](https://github.com/michaelkrauty/steamvr-oculus-touch/blob/v0.3.0/docs/validation.md).
